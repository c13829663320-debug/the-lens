## 状态与接入规则

| 状态 | 含义 | 是否可进入生产 manifest |
|---|---|---|
| `pending_generation` | 只有镜头表和提示词，尚未生成或没有可验证输出 | 否 |
| `draft_needs_art_review` | 文件存在并通过基础媒体检查，等待美术逐帧确认 | 否；可以在独立服务中作为草稿预览 |
| `approved` | 叙事、构图、逐帧画面和转码均签字，hash 已记录 | 是 |
| `rejected` | 与剧本、素材包或画面边界冲突 | 否，移出发布目录 |

manifest 只登记 `server/media/` 中已经存在且可读取的文件。待生成镜头只出现在本表，不创建空文件、占位视频或虚构 URL。`data/media.js` 在获得美术批准、hash、HTTPS 和微信合法域名证据前保持空的远程 `baseUrl/clips`；缺少 CG 时由包内静帧承载剧情。

## 命名与版本

视频使用 `cg_<scene>_<shot>_t<两位take>_v<两位版本>_<resolution>.mp4`。例如 `cg_s02_lens_reveal_t01_v01_720p.mp4`。现有 S01 历史文件 `cg_s01_reveal_720p_v1.mp4` 保留原名，不为迁移命名而重编码或复制。

- `t01` 表示一次独立生成/选片；同一生成任务的修订只增加 `v02`、`v03`。
- 重新生成必须保留源任务 ID、模型版本、提示词、参数、日期和失败/退款信息；不得用价格字段推断货币或已扣费。
- 进入 `approved` 前必须记录字节数、SHA-256、容器/编码、分辨率、帧率、时长、音频轨和人工审核人；裁切、转码或替换内容都要产生新版本。
- 文件名中的状态不作为审核依据，状态以 manifest 字段和审核记录为准。

## 审核清单

逐镜头由编剧/美术/技术分别确认，并把结果与 hash 放在对应审核记录中：

- [ ] 文件真实存在、可读取，扩展名与 MIME 一致；`ffprobe` 能读出容器、轨道、时长、分辨率、帧率。
- [ ] 首帧、中帧、尾帧接触表已查看，画面无乱码、logo、水印、模型残影、肢体变形或穿模。
- [ ] 现实与历史影像空间同构；断墙、地面缺口、人物比例、镜片五个刻点在镜头内稳定。
- [ ] 影像不改变现实物体，不承重，不创造可交互道具；S02 真实罐头仍由关镜后的现实行动取得。
- [ ] 阿迟、小花、族长外观与素材包参考一致，服装、受伤、救援和透镜耗电符合剧本固定因果。
- [ ] S09 透镜断电后仅保留无源观察框；片尾不展示阿迟去向、彩色奇迹、额外旁白或总结。
- [ ] 无 UI/字幕依赖；首尾有可裁切安全帧，音频无语音/音乐侵权或突兀爆音。
- [ ] 微信目标格式、体积、首尾跳过行为在服务端和预览环境检查；真机结论单独记录，不能用浏览器/开发者工具代替。
- [ ] 审核人明确签字为 `approved` 或记录具体退回原因；未签字一律 `draft_needs_art_review`/`pending_generation`。
